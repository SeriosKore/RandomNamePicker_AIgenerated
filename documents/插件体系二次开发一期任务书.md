## §0 已确认决策（拍板后实施时不得更改）

### 0.1 范围决策

- **D1 一期范围 = 《建议》P0-1~P0-4 全部 + D1~D9 文档修订**（档A）。不含《建议》P1/P2 各项与“只做三件事”最小集（两者均不另行单独立项，见 §7 后续展望）。

### 0.2 API 面与边界（P0-1）

- **D2 公开 API 面定义**（本期末形成权威口径，落 `plugin/HostApi.java` 的 javadoc）：
  - 受支持公开面 = `plugin` 包全部 + `mode` 包 `ModeHandler/ModeHost` + `model` 只读类（`Scheme/NumberRange/SeatConfig` 只读用法）+ `PluginContext` 提供句柄的 Manager（`NameManager/SchemeManager/DataManager/LogManager`）的方法子集；
  - 其余（`PasswordManager/ConfigManager/FloatingBall/NamePickerApp`、`ui/floating/theme/main` 各包、`core` 静态入口）为**宿主内部、不承诺兼容**；第三方不得依赖，宿主也不保证其可见性维持不变。
- **D3 打包禁令可校验**：`PluginManager` 扫描 jar 时发现任何 `com/randomnamepicker/` 前缀的 class 条目 → **整 jar 拒载**（原仅文档约束，本期升为宿主强制），原因码 `BUNDLED_HOST_CLASS`，日志含首个违规条目类名。
- **D4 收紧静态旁路**：`ModeRegistry.register/unregister` 由 `public static` 改 **package-private**（已核：全仓库无外部调用，仅类内静态块自用）；同步修正其 javadoc（原“Stage3 插件注册入口”表述废止）。
- **D5 信任模型如实化**：《插件开发文档.md》显式声明“插件 = 与本程序同权限的可执行代码（完全信任模型），`PasswordManager/ConfigManager` 等类型在编译期可达、运行期可反射，使用即脱离公开 API”。一期**不做**沙箱/签名/首启确认弹窗（见 §7）。

### 0.3 事件与观察（P0-2 / P0-3）

- **D6 一期事件集**：`PLUGINS_CHANGED / SCHEME_CHANGED / MODE_CHANGED / PICK_STARTED / PICK_FINISHED / LOCK_CHANGED` 六类。
  - `PICK_*` 覆盖主窗与悬浮球两条抽取路径（主窗含被 `canPick()` 拦截的“未抽取成功”出口，按 PICK_FINISHED + 空结果/拦截原因载荷发）；
  - `LOCK_CHANGED` 收敛到 UI 层正常出口：`SettingsWindow.toggleLock`、`PasswordDialog/OldPasswordDialog` 验证成功分支；**Ctrl+L×10 后门不派发**（已知边界，注释说明；如需补 PasswordManager 侧钩子列后续）。
  - 一期**不做**窗口几何订阅/悬浮球位置查询等“窗口级能力”（属《建议》P0-2.4，列 §7 后续）。
- **D7 事件语义**：事件载荷为不可变值对象；**EDT 派发**；逐监听器 try/catch（异常记日志，不影响其它监听器）；订阅登记在 `PluginManager` 并按插件归属，**onUnload / 整 jar 拒载回滚时宿主自动清理**（插件无需也不得在退订上依赖顺序）。`PluginContext` 新增 `addHostEventListener/removeHostEventListener`；`Plugin` 接口零改动。
- **D8 版本契约**：宿主在 `HostApi` 暴露 `HOST_VERSION`（与当前交付版本一致）与整数 `API_LEVEL`（起始 =1）；插件可经 jar `MANIFEST.MF` 声明 `Host-Version-Min / Host-Version-Max`（可选）。**声明了才校验**：不满足 → 整 jar 拒载，原因码 `VERSION_MISMATCH`，日志含期望/实际版本；未声明的旧插件照常加载（向后兼容）。
- **D9 加载结果可观测**：`PluginManager` 为每个 jar 保留 `LoadOutcome {jar 名, 状态 LOADED/REJECTED, 成功插件“名称 版本”清单, 原因码 + 原因文案, 时间戳}`，提供只读查询 `getLoadHistory()` / `getLoadOutcome(jar)`。拒载原因码枚举 `RejectReason`（`CLASS_LOAD_FAIL / INSTANTIATE_FAIL / ONLOAD_FAIL / COMMIT_CONFLICT / NULL_ZONE / BUNDLED_HOST_CLASS / VERSION_MISMATCH / UNEXPECTED`），每个码配“建议文案”（对齐《插件开发文档.md》§11 调试速查）。
- **D10 状态 UI 入口**：主窗“插件”菜单尾新增可点击项“插件状态…”（打开只读模态对话框：成功清单 / 拒载清单 + 原因与建议）。**仅当 `plugins/` 下存在 jar（outcomes 非空）时该项出现**；无任何 jar 时菜单与现状零差异。说明：被拒 jar 场景下该项出现属**预期新增**（原为只读日志），不视为回归。

### 0.4 兼容红线

- **D11 二进制兼容**：`Plugin/UiZone/ModeHandler/ModeHost` 既有方法语义不变；`Plugin` 接口不加方法（版本契约走 Manifest）；`PluginContext` 只增不改既有方法语义；既有插件（ExamplePlugin、plugin-qa、用户已装 jar）零改动可继续运行。
- **D12 `RollingPicker` 完成回调**：为悬浮球 `PICK_FINISHED` 增加**可选**自动停完成回调（仅 `maxTicks` 滚满自停路径触发；默认 null = 现行为零变化），主窗路径不动。
- **D13 文档同批交付**：《插件开发文档.md》按 D1~D9 修订、`README.txt`（§0 进度表 / 类计数 / 插件区说明）在本次一并更新，纳入验收，不遗留“代码先行文档滞后”。
- **D14 交付与备份**：实施前将待改源码快照至 `.plugin3_originals/`；交付《插件体系二次开发一期交付报告.md》；重建 `RandomNamePicker.jar`；README/交接说明同步。

## §1 目标与设计不变式

1. 目标：在**不动加载内核与既有契约**的前提下，把“插件体系对第三方开放”补齐四块地基——① 可校验的 API 边界；② 宿主状态事件化；③ 加载结果可观测；④ 插件/宿主版本契约；并把《插件开发文档.md》与上述实现、与真实信任模型对齐。
2. 事件统一走“**宿主收敛出口 → PluginManager 分发（EDT、防御）**”，不新增 core→plugin 依赖方向（`PasswordManager` 等 core 类不 import plugin 包）。
3. 状态与版本校验均为加载期增量；查询只读快照；所有新方法均可选/default/新增接口形态，旧插件不感知。
4. “无插件零差异”红线维持，但仅针对**无任何 jar**；有 jar（无论成败）时新增状态入口为有意行为。
5. 所有对第三方可见的规则（打包禁令、版本声明、信任模型、事件订阅）必须在《插件开发文档.md》与 javadoc 双重成文，验收要求文档与代码一致。

## §3 实施任务分解（批准后按 T0–T13 执行）

## §4 不改动（保真红线）

- `Plugin/UiZone/ModeHandler/ModeHost` 既有方法与语义不改；`Plugin` 接口不加方法（版本契约走 Manifest，D11）。
- 加载内核（整 jar 原子事务/暂存-提交/冲突预检/EDT 刷新时序）不改，只在其出口加记录与分发。
- 不新增 core→plugin 依赖（`PasswordManager/ConfigManager/DataManager` 等 core 类不引用 plugin 包；事件一律在 ui/floating 收敛出口触发）。
- 既有行为不改：菜单/模式/托盘/悬浮球/抽取/锁/加密/主题/三备份自愈；内置三模式回归必须零差异。
- 既有插件（ExamplePlugin、plugin-qa、用户已装 jar）零改动可运行：未声明 Manifest 版本视为兼容、未订阅事件不受影响、监听随卸载自动清理。
- 无任何 jar 时主窗“插件”菜单与全部窗口零差异（有拒载 jar 时新增“插件状态…”入口属预期，见 D10）。
- 本任务书阶段不实施 P1/P2 与热插拔等（见 §7）。

## §5 风险与对策

| 风险 | 对策 |
|---|---|
| 打包禁令由“文档约束”升为“强制拒载”可能误伤历史 jar（曾侥幸带宿主类但仍能加载） | D3 语义明确并写文档红线；QA `BadBundlePlugin` 验证；验收用例覆盖“仅文档时代旧 jar”需按新规则重打（明确在交付报告中提示） |
| Manifest 解析/版本比较边界（缺属性、非数字、比较基准） | 未声明=不校验（向后兼容）；解析失败视为未声明；`VERSION_MISMATCH` 日志同时打印期望/实际串，便于排查 |
| 事件派发引发循环或重入（如监听器内再次触发宿主动作） | 分发为同步单次快照拷贝（对齐 `notifyUIListeners` 现状），监听器异常 try/catch；文档规定监听器内不得依赖派发顺序、不得在回调中阻塞 EDT |
| 订阅泄漏：插件忘记退订 | 宿主在 onUnload/拒载回滚按插件自动清理（D7）；`plugin-events-demo` 演示 onUnload 显式退订的双保险写法 |
| 悬浮球 `PICK_FINISHED` 需在 20 次自停后触发，误伤主窗 | `RollingPicker` 完成回调仅 maxTicks 自动停路径触发、默认 null 零变化；主窗路径不接回调（D12） |
| `LOCK_CHANGED` 出口零散漏接 | 收敛 3 个正常出口（D6）；Ctrl+L 后门不派发为**明确已知边界**并在代码注释与文档标注；验收覆盖锁定/解锁动作 |
| 状态 UI 破坏“无插件零差异” | 入口仅在 outcomes 非空出现（D10）；none 场景断言菜单与现版一致 |
| ModeRegistry 改可见性漏改调用点 | 已全仓库核对无外部调用；改后全量 javac + 内置模式回归兜底 |
| 文档与实现不同步 | D13 要求文档修订与代码同批交付；验收含“文档声明 ↔ 代码行为”抽查清单 |

## §6 验收标准

1. 编译零错误（全量 javac）；主 jar 重建；无第三方依赖新增。
2. **none 场景**：`plugins/` 无任何 jar → 主窗“插件”菜单与全部窗口与现版零差异；无“插件状态…”项。
3. **旧插件回归**：仅 ExamplePlugin / 用户未声明版本 jar → 照常加载（菜单/模式/Zone 如旧）；`PLUGIN_LOADED` 正常。
4. **打包禁令**：放入 `BadBundlePlugin.jar` → 整 jar 拒载，日志含 `BUNDLED_HOST_CLASS` 与首个违规类名；好插件不受影响；无 UI 残留。
5. **版本契约**：放入 `BadVersionPlugin.jar`（Min-Host-Version 过高）→ 整 jar 拒载 `VERSION_MISMATCH`，日志含期望/实际；去掉声明或改低 → 照常加载。
6. **ModeRegistry 收紧**：内置三模式下拉框/方案类型联动/抽取行为与现版一致；示例插件模式不受影响。
7. **事件订阅**（`plugin-events-demo`）：启动后主窗抽取一轮 → 订阅方收到 `PICK_STARTED/PICK_FINISHED`（载荷含方案/模式/结果）；切换方案/模式 → 收到 `SCHEME_CHANGED/MODE_CHANGED`；悬浮球双击抽取 → 收到 source=BALL 的 `PICK_*`；锁定/解锁 → 收到 `LOCK_CHANGED`（Ctrl+L 后门除外）；卸载/拒载后不再收到（自动清理验证）。
8. **状态可观测**：放入混合场景（好 jar + `BadBundlePlugin` + `BadVersionPlugin`）重启 → 主窗“插件”菜单尾出现“插件状态…”；打开对话框可见 成功清单 + 拒载清单（原因码与建议文案正确）；shutdown `PLUGIN_UNLOADED` 完整。
9. **文档一致**：《插件开发文档.md》修订项（§3-T12 的 9 条）逐条落实且与代码行为一致；`README.txt` 进度表/类计数/新示例与 QA 已同步。
10. **零改动复核**：`git diff -- src/`（或对照 `.plugin3_originals/`）显示改动仅限 §2 清单内文件；`Plugin/UiZone/ModeHandler/ModeHost` 无方法级改动。
