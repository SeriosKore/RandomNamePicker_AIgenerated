## §0 已确认决策（拍板后实施时不得更改）

### 0.1 范围决策

- **D1 一期范围 = 《建议》P0-1~P0-4 全部 + D1~D9 文档修订（档A）＋ 追加窗口级钩子 G1/G2/G4 与锁后门 G5**（用户拍板）。不含《建议》P1/P2 其余各项与“只做三件事”最小集（见 §7）。
- **D1a Q&A 拍板结论**（用户定稿）：
  - Q2：`PICK_STARTED/PICK_FINISHED` **仅在“真实发生抽取”的路径派发**；`canPick()` 拦截、数据缺失等未抽取出口不派发。
  - Q3：`SCHEME_CHANGED/MODE_CHANGED` **仅用户操作引起且状态真实翻转**时派发；启动恢复方案、方案管理关闭后 `loadSchemes()` 重载、插件集刷新保持选中等程序化刷新**不派发**（suppress 标志）。
  - Q5/G5：`LOCK_CHANGED` 做事件 + `PluginContext` 提供只读 `default boolean isHostLocked()`；**Ctrl+L×10 后门必须纳入**，实现取**最简**（见 D7：宿主内部去重小方法 + 各既有 UI 翻转点追加一行；`PasswordManager` **零改动**，不引入回调注册/桥接架构）。
  - G 拍板：**窗口级钩子 G1（悬浮球只读几何查询）、G2（悬浮球生命周期/几何事件）、G4（模式专属悬浮球右键菜单口子）纳入一期；G3（悬浮球交互观察官方化）不做（维持观察式，见 §7）。**

### 0.2 API 面与边界（P0-1）

- **D2 公开 API 面定义**（本期末形成权威口径，落 `plugin/HostApi.java` 的 javadoc）：
  - 受支持公开面 = `plugin` 包全部 + `mode` 包 `ModeHandler/ModeHost`（含本期新增只读查询与 default 方法）+ `model` 只读类（`Scheme/NumberRange/SeatConfig` 只读用法）+ `PluginContext` 提供句柄的 Manager（`NameManager/SchemeManager/DataManager/LogManager`）的方法子集；
  - 其余（`PasswordManager/ConfigManager/FloatingBall/NamePickerApp`、`ui/floating/theme/main` 各包、`core` 静态入口）为**宿主内部、不承诺兼容**。
- **D3 打包禁令 → 立即强制拒载（Q1=A）**：
  - 检查对象：jar 内 **`.class` 条目**且以 `com/randomnamepicker/` 开头；与类扫描同过滤集（已排除 `module-info.class` 与 `META-INF/versions/`，另整体排除 `META-INF/`）。**资源文件不在检查范围**。
  - 命中 → **整 jar 拒载**，原因码 `BUNDLED_HOST_CLASS`，日志含首个违规条目类名。
  - 本仓库 8 个已交付 jar 经 `jar tf` 实证零宿主条目，零影响；正常 import/反射引用宿主 API 的插件不受影响（条目检查不查引用）。
  - 文档同步：打包自检命令 + “违规=拒载”语义；交付报告提示外部违规存量 jar 需重打（一次性）。
- **D4 收紧静态旁路**：`ModeRegistry.register/unregister` 由 `public static` 改 **package-private**（已核：全仓库无外部调用，仅类内静态块自用）；同步修正其 javadoc（原“Stage3 插件注册入口”表述废止）。
- **D5 信任模型如实化**：《插件开发文档.md》显式声明“插件 = 与本程序同权限的可执行代码（完全信任模型），`PasswordManager/ConfigManager` 等类型在编译期可达、运行期可反射，使用即脱离公开 API”。一期**不做**沙箱/签名/首启确认弹窗（见 §7）。

### 0.3 事件与观察（P0-2 / P0-3 + G1/G2/G4/G5）

- **D6 一期事件集与派发语义**（六类 → **九类**；含 Q2/Q3/Q5/G2/G5 与 F1/F3）：
  - 事件类型：`PLUGINS_CHANGED / SCHEME_CHANGED / MODE_CHANGED / PICK_STARTED / PICK_FINISHED / LOCK_CHANGED / BALL_SHOWN / BALL_HIDDEN / BALL_MOVED`。
  - `PICK_*`（Q2）：仅真实抽取派发——主窗 `canPick()` 通过并启动滚动 → `PICK_STARTED`；滚动停止定格 → `PICK_FINISHED`（含触发源 MAIN/BALL）。`canPick()` 拦截、数据缺失等出口**不发**。
  - `SCHEME_CHANGED / MODE_CHANGED`（Q3+F3）：仅用户驱动且真实翻转；启动恢复方案、方案管理关闭后 `loadSchemes()` 重载、插件集刷新保持选中等程序化刷新**不派发**（scheme/mode suppress 标志）。**例外（F3）：用户切换方案触发的“方案类型→模式”自动联动产生的 MODE_CHANGED 视为用户驱动、照常派发**（suppress 只屏蔽 启动恢复/对话框重载/插件集刷新 三类程序化路径，不屏蔽用户切换链路）。
  - `LOCK_CHANGED`（Q5/G5）：在各**既有 UI 翻转点动作后**（`SettingsWindow.toggleLock` 锁定/解锁分支、`PasswordDialog/OldPasswordDialog` 验证成功分支、四个密码对话框 `handleCtrlLShortcut()` 第 10 次成功分支即 Ctrl+L 后门）追加一行调用宿主内部去重小方法（见 D7）；仅真实翻转派发（去重由该方法内部完成）。**`PasswordManager` 不改动**。
  - `BALL_SHOWN / BALL_HIDDEN`（G2）：悬浮球实例显示 / 隐藏-销毁时派发，载荷含当前 bounds。
  - `BALL_MOVED`（G2+F1）：悬浮球几何（位置/尺寸）变化时派发（节流规则见 D16）；载荷含 old/new bounds（Rectangle 含尺寸，将来若宿主加“实时改径”，尺寸变化也经本事件观察）；**不设独立 BALL_RESIZED**（当前产品流程无运行期改径路径，避免不可达死 API）。
  - 一期**不做** G3 悬浮球交互观察官方化（单击/双击/拖动判定仍由插件观察式实现；文档 D5 允许灰色 instanceof/几何观察）。
- **D7 事件语义与依赖方向**：载荷为不可变值对象（含 `java.awt.Rectangle` 副本等值类型，不泄漏宿主 UI 对象）；**EDT 派发**；逐监听器 try/catch（异常记日志，不影响其它监听器）；订阅登记在 `PluginManager`，归属键 = **jar 文件名 + 插件实现类全名**（唯一，F2——插件名 `getName()` 可重复，冲突预检只查 modeId/displayName，故不得以插件名作清理键）；**onUnload / 整 jar 拒载回滚 / onLoad 抛异常候选**均按该唯一键自动清理（防泄漏）。订阅在提交前登记、**提交成功后激活**（pending 阶段不收事件；拒载整组丢弃）。
  - `LOCK_CHANGED` 最简实现：**不动 `PasswordManager`（core 零改动）**。在 `PluginManager`（plugin 包，UI 层已依赖）提供一个宿主内部去重小方法，如 `notifyLockStateIfChanged()`：读取当前 `PasswordManager.isLocked()`，与内部记录的上次已派发锁态比较，翻转才派发 `LOCK_CHANGED`（EDT、走统一 `dispatchHostEvent` 分发），并更新记录；首次调用仅记录不派发。各既有 UI 翻转点动作后各追加一行调用该小方法（SettingsWindow 锁/解锁两分支、PasswordDialog/OldPasswordDialog 验证成功分支、ChangePasswordDialog/NewPasswordDialog/OldPasswordDialog/PasswordDialog 的 Ctrl+L×10 成功分支）。无回调注册、无 init/shutdown 桥接、无 setter 改造。
  - `PluginContext` 新增 `addHostEventListener/removeHostEventListener` 与只读 default `getHostVersion()/getApiLevel()/isHostLocked()`；`Plugin` 接口零改动。
- **D8 版本度量与门控（Q4=B′）**：产品版本号与兼容门控**解耦**。
  - `HOST_VERSION`（x.y.z，产品发布号）：每次交付递增；用于 UI/日志/文档/打包命名；**不参与门控**。
  - `PLUGIN_API_LEVEL`（整数）：**唯一兼容门控**。插件经 jar `MANIFEST.MF` 声明 `Api-Level-Min`（可选）；宿主门控 = 当前级别 ≥ 声明值；**未声明/无法解析 = 视为未声明 = 照常加载**（向后兼容底线）；不满足 → 整 jar 拒载，原因码 `VERSION_MISMATCH`，日志含“需要 ≥N、当前 M”。
  - **不设 Max、不做 Host-Version 门控、不做双轨**。
- **D8b API 级别增量纪律**（Q4 追问，必须写死）：
  - 基线：V1.1.0 既有公开面追溯 = 级别 **1**；本期新增公开 API（事件订阅/HostEvent 九类/isHostLocked/ModeHost 几何查询/ModeHandler 右键口子/状态查询等）→ 交付时级别 = **2**（同一交付单元一次 +1，不按 API 数累加）。
  - 判一次/交付单元：含插件面变更 → +1；不含 → 不变。触发 +1：新增/删除/改名公开 API（方法、事件类型、UiZone 值、只读查询、公开类）；破坏性/语义契约变更（配 ≥1 版本弃用期 + 破坏性清单）。不触发 +1：纯内部改动（默认密码、加密内部算法、托盘图标、主题内部实现等）。
  - 强制落地：交付报告必须记录“API 级别 X→Y + 理由”；《插件开发文档.md》维护“API 级别变更表”；验收含该条目。
- **D9 加载结果可观测**：`PluginManager` 为每个 jar 保留 `LoadOutcome {jar 名, 状态 LOADED/REJECTED, 成功插件“名称 版本”清单, 原因码 + 原因文案, 时间戳}`，提供只读查询 `getLoadHistory()` / `getLoadOutcome(jar)`。拒载原因码枚举 `RejectReason`（`CLASS_LOAD_FAIL / INSTANTIATE_FAIL / ONLOAD_FAIL / COMMIT_CONFLICT / NULL_ZONE / BUNDLED_HOST_CLASS / VERSION_MISMATCH / UNEXPECTED`），每个码配“建议文案”（对齐《插件开发文档.md》§11 调试速查）。
- **D10 状态 UI 入口**：主窗“插件”菜单尾新增可点击项“插件状态…”（打开只读模态对话框：成功清单 / 拒载清单 + 原因与建议）。**仅当 outcomes 非空时该项出现**；无任何 jar 时菜单与现状零差异。说明：被拒 jar 场景下该项出现属**预期新增**，不视为回归。

### 0.4 窗口级钩子（G1/G2/G4 决策）

- **D15 G1 悬浮球只读几何查询**：`ModeHost` 新增只读方法（单实现者 `NamePickerApp` 同步实现）：
  - `boolean isFloatingBallVisible();`
  - `java.awt.Rectangle getFloatingBallBounds();`（未建/不可见时返回 null）
  - `java.awt.Rectangle getMainWindowBounds();`
  - 语义：EDT 读取、快照查询；替代插件 `Window.getWindows()+instanceof FloatingBall` 的“找球”轮询；只读，不改变宿主任何状态；不新增线程。
- **D16 G2 悬浮球生命周期/几何事件**：
  - `BALL_SHOWN`：新建并显示后发（含初始 bounds）；`BALL_HIDDEN`：隐藏/销毁后发。
  - `BALL_MOVED`：位置或尺寸变化即发（F1——不设独立 BALL_RESIZED；当前产品无运行期改径路径）；载荷含 old/new bounds 的 `Rectangle` 副本。
  - **节流规则**：几何检测复用在 `FloatingBall` 既有 `keepTopTimer`（100ms）内做前后 bounds 比对；同一 tick 合并；位移/尺寸变化 ≥1px 才发（上限约 10 次/秒）；EDT 内派发。
  - 触发点收敛：`NamePickerApp.showFloatingBall()/hideFloatingBall()` 与 `FloatingBall.dispose()` 路径补 `BALL_SHOWN/BALL_HIDDEN`；几何变化在 `FloatingBall` 内自报。
  - 不改变悬浮球既有交互行为（拖动/双击/右键结构/置顶逻辑）。
- **D17 G4 模式专属悬浮球右键菜单口子**：
  - `ModeHandler` 新增 **default 方法**（默认返回空 = 无模式专属项，不破坏既有子类）：
    - `default java.util.List<ModeHandler.ModeMenuItem> getContextMenuItems()`；`ModeMenuItem` 为 `ModeHandler` 内嵌套值类型（title + `ActionListener`）。
  - `FloatingBall.createDynamicPopupMenu`：当前模式为**内置三项**（以 modeId 判，保留现有“配置名单/数字设置/座位设置”文案与动作，内部不再按显示名 switch）→ 菜单与现版逐项一致；当前模式为**插件模式** → 追加其 `getContextMenuItems()` 项（宿主防御执行）。
  - 生效语义沿用现状：悬浮球右键菜单在**每次新建悬浮球实例**时读取当前模式（文档已述）；切换模式后需重开悬浮球。
  - 插件模式专属项不得影响内置模式菜单（回归断言）。
- **D18 受控红线豁免**：`ModeHost` 仅**新增只读查询**方法、`ModeHandler` 仅**新增 default** 方法、`FloatingBall` 仅新增事件检测与菜单读取（不改既有交互行为）、`PasswordManager` **零改动**（锁事件由 UI 层既有翻转点 + PluginManager 内部去重小方法派发）；以上均不视为破坏既有契约（D11）。

## §1 目标与设计不变式

1. 目标：在**不动加载内核与既有契约**的前提下补齐地基——① 可校验的 API 边界（打包禁令强制、公开面定稿、静态旁路收紧）；② 宿主状态事件化（**九类事件** + 严格语义 + 锁后门纳入）；③ 加载结果可观测（LoadOutcome + 状态 UI）；④ API 级别门控 + 增量纪律；⑤ 悬浮球官方窗口钩子（G1 几何只读查询 / G2 生命周期与几何事件 / G4 模式专属右键菜单口子）。
2. 事件统一走“**宿主收敛出口 → PluginManager 分发（EDT、防御）**”；**core 零改动、不新增依赖方向**（锁事件 = 各既有 UI 翻转点动作后调 `PluginManager` 内部去重小方法，`PasswordManager` 不改，依赖方向仍为 ui/plugin→core，与现状一致）。
3. 版本度量：`HOST_VERSION` 展示不门控；`PLUGIN_API_LEVEL` 唯一门控且按 D8b 纪律维护。
4. G1/G2 不新增线程：几何检测复用 `FloatingBall.keepTopTimer` 既有 100ms tick；查询为 EDT 快照；不改变悬浮球交互行为。
5. “无插件零差异”红线维持，仅针对**无任何 jar**；有 jar（无论成败）时状态入口出现为有意行为（D10）。
6. 所有对第三方可见的规则（打包禁令、API 级别、事件/钩子语义、信任模型）必须在《插件开发文档.md》与 javadoc 双重成文，验收要求文档与代码一致。

## §6 验收标准

1. 编译零错误（全量 javac）；主 jar 重建；无第三方依赖新增。
2. **none 场景**：`plugins/` 无任何 jar → 主窗“插件”菜单与全部窗口与现版零差异；无“插件状态…”项。
3. **旧插件回归**：仅 ExamplePlugin / 未声明 `Api-Level-Min` 的 jar → 照常加载（菜单/模式/Zone 如旧）；`PLUGIN_LOADED` 正常。
4. **打包禁令**：放入 `BadBundlePlugin.jar` → 整 jar 拒载，日志含 `BUNDLED_HOST_CLASS` 与首个违规类名；好插件不受影响；无 UI 残留。
5. **API 级别门控**：放入 `BadVersionPlugin.jar`（`Api-Level-Min: 9999`）→ 整 jar 拒载 `VERSION_MISMATCH`，日志含“需要 ≥9999、当前 2”；声明 `Api-Level-Min: 2` 或未声明 → 照常加载。
6. **API 级别纪律**：`HostApi.PLUGIN_API_LEVEL = 2`（基线 1 + 本期公开 API +1）；交付报告含“API 级别：1→2（理由）”；《插件开发文档.md》含“API 级别变更表”且与交付一致。
7. **ModeRegistry 收紧**：内置三模式下拉框/方案类型联动/抽取行为与现版一致；示例插件模式不受影响。
8. **事件订阅**（`plugin-events-demo`）：
   - 主窗真实抽取一轮 → 收到 `PICK_STARTED/PICK_FINISHED`（载荷含方案/模式 displayName+modeId/结果）；
   - **数据缺失等拦截路径 → 不收到 PICK 事件**（Q2）；
   - 用户切换方案/模式 → 收到 `SCHEME_CHANGED/MODE_CHANGED`；**启动恢复/方案管理后重载/插件集刷新 → 不收到**（Q3）；**用户切换方案触发的方案→模式自动联动 → 收到 MODE_CHANGED**（F3）；
   - 悬浮球双击抽取 → 收到 source=BALL 的 `PICK_*`；
   - 锁定/解锁/**Ctrl+L×10** → 各收到一次 `LOCK_CHANGED`（无重复）；`isHostLocked()` 与当前锁态一致；
   - 卸载/拒载/onLoad 失败后不再收到（自动清理验证，归属键 = jar 文件名 + 实现类全名，F2）。
9. **窗口钩子（G1/G2/G4）**：
   - G1：打开悬浮球后 `isFloatingBallVisible()=true`、`getFloatingBallBounds()` ≈ 实际球位置与尺寸；隐藏/关闭后 `false`/`null`；`getMainWindowBounds()` 与主窗一致；
   - G2：打开球 → 收到 `BALL_SHOWN`（含初始 bounds）；拖动球 → 收到 `BALL_MOVED`（节流生效、载荷 old/new 正确）；隐藏/关闭 → 收到 `BALL_HIDDEN`；**无独立 BALL_RESIZED 事件（F1）**；悬浮球拖动/双击抽取/置顶行为与现版一致（回归）；
   - G4：当前模式为**内置** → 悬浮球右键菜单与现版逐项一致；当前模式为插件模式（demo 注册的模式）→ 出现其“模式专属项”且点击动作正确；切换模式后重开悬浮球，项随当前模式变化；插件模式专属项不出现在内置模式。
10. **状态可观测**：混合场景（好 jar + `BadBundlePlugin` + `BadVersionPlugin`）重启 → “插件状态…”出现；对话框可见成功清单与拒载清单（原因码/建议正确）；shutdown `PLUGIN_UNLOADED` 完整。
11. **文档一致**：《插件开发文档.md》修订项（§3-T12 的 10 条）逐条落实且与代码行为一致；`README.txt` 进度表/类计数/API 级别/九类事件/窗口钩子已同步。
12. **零改动复核**：`git diff -- src/`（或对照 `.plugin3_originals/`）显示改动仅限 §2 清单内文件；`Plugin/UiZone` 无方法级改动；`ModeHost/ModeHandler` 仅新增方法；**`core/PasswordManager.java` 零改动（无 diff）**。
