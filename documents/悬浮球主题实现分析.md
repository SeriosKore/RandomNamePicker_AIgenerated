# 悬浮球主题实现分析

> 评审对象：RandomNamePicker V1.1.0（宿主 API 级别 2）
> 评审需求：**① 悬浮球换皮——由默认蓝色改为可导入照片作为球体底图；② 抽奖动画插件化实现。**
> 评审方式：**只读交叉比对**（需求 ↔ 宿主源码 ↔ 插件公开 API ↔ 既有主题引擎 ↔ 既有示例插件），未修改任何源码、文档或产物，仅新增本分析文件。
> 评审产出：风险点清单（§5）+ 改进路径（§6），并按用户要求分两种情况讨论——**方案 A：不改源码、纯插件实现**；**方案 B：改动源码实现**。
> 证据引用统一为 `文件:行号`；结论均为设计草案，不含已落地代码。

## 0. 结论速览（TL;DR）

| 需求子项 | 方案 A（不改源码，纯插件） | 方案 B（改源码） | 建议 |
|---|---|---|---|
| 悬浮球由蓝色改为照片球皮 | **形似可实现，工程上不可承诺**：只能"覆盖式蒙皮"（往球窗内容层塞自绘组件或叠一个同位置窗口），必须自己重实现拖动/双击等输入转发 | **干净可实现**：球皮解析 + 预缩放缓存 + 设置项 + 圆形裁切，可复用现有 `theme` 引擎大半能力 | **B** |
| 导入照片（图库/裁切/持久化） | 可行（插件自持 `data/<插件名>/`、自建导入与裁切 UI、注册 `FLOATING_BALL_MENU`/`SETTINGS_WINDOW` 动作） | 可行（复用 `ThemeStore.importImage`/`CropSelectorDialog`） | A/B 均可，B 一致性好 |
| 抽奖动画**插件化**（可替换的逐帧呈现） | **不可实现**：宿主把显示写死为 `Consumer<String>` → `JLabel.setText`，插件在 PICK_STARTED 与 PICK_FINISHED 之间拿不到帧回调，只能整段"遮罩式伪动画" | **可实现**：把"取样"与"播放"解耦，抽出 `RollPresenter` 呈现层 + 插件注册 SPI | **B** |
| 动画时长/节奏/素材可控 | **不可实现**（20×50ms 硬编码，插件无法改） | 可实现（宿主统一帧驱动 + 动画声明时长） | **B** |
| 与既有"悬浮球主题豁免铁律"一致 | 不涉及宿主引擎，但与既有口径表述冲突需澄清 | 需先把"球体皮肤"与"窗口整面背景贴图"两个概念切开 | 两者都需先改口径 |
| 抽取公平性/结果口径不变 | 只能观察，不能改（好） | 须在设计上刚性保证"动画不得改变结果" | 两者都必须守住 |

**一句话结论：照片球皮在方案 A 下只能做成"覆盖蒙皮"的灰色实现（形似、易碎、输入交互要自己重造），抽奖动画插件化在方案 A 下从根本上做不到；两项需求都建议走方案 B，且 B 可以分成"宿主内建球皮（B1）→ 宿主动画呈现层抽象（B2）→ 插件 SPI（B3）"三步，B1/B2 就能满足产品侧 90% 的观感诉求，B3 才是"插件化"的那一步。**

## 1. 需求解析与口径确认

### 1.1 需求拆解

| 编号 | 需求 | 可验收的客观口径（建议） |
|---|---|---|
| R-A1 | 悬浮球默认蓝色 → 可导入照片作为球体底图 | 设置项可选照片；球面按所选绘制模式铺满；无照片时**逐像素等价**于现版蓝圆（保真回退） |
| R-A2 | 照片可在球面内定位/裁切 | 复用现有 `BackdropMode`（填充/适应/拉伸/居中）与自由裁切框 |
| R-A3 | 半透明度语义保持可用 | 现"透明度"滑杆对照片球继续生效（作用于整个球体图层） |
| R-A4 | 球上文字（"抽取"与滚动结果）在照片上仍可读 | 文字描边/阴影或自动压暗；默认开启 |
| R-B1 | 抽奖动画可替换/可插拔 | 呈现层为独立可替换单元，内置默认=现状（文字滚动），插件可提供新动画 |
| R-B2 | 动画不改变抽取结果与节奏口径 | 结果仍由"第 20 次候选"决定；日志 `方案-模式显示名=结果` 与 `PICK_FINISHED` 语义不变 |
| R-B3 | 动画异常不影响抽取 | 渲染异常/超时 → 回退默认呈现，不弹崩溃、不中断抽取 |
| R-B4 | 动画可卸载还原 | 插件卸载/拒载回滚 → 立即回退默认呈现，无残留 |

### 1.2 必须先确认的口径（待确认项，见 §8）

`"可以导入底部照片"` 存在歧义，直接决定渲染架构：

- **口径甲（推荐，按球体皮肤理解）**：导入的照片作为**球体自身底图**（圆形裁切，球=照片）。
- **口径乙**：照片作为**悬浮球背后的托底/底座**（球下方一块照片牌），球体本身仍是蓝色或半透明。
- **口径丙**：照片作为**球窗整面背景**（球窗矩形区域贴图，含四角），即把悬浮球纳入"窗口背景贴图"体系。

三者的实现代价与风险差别很大：甲最干净、可完全复用现有主题渲染与裁切；乙需要重排球窗布局（球窗尺寸=球+底座，会连带影响 `FloatingBallTracker` 的尺寸/方位推导，见 R-14）；**丙与既有"悬浮球豁免贴图"铁律直接冲突**（`documents/交接说明.md:39`、`documents/2_宿主代码主题实现.md:43,59`），且会让球窗矩形区（含圆外四角）出图，视觉上变成"方块球"。

### 1.3 与既有设计口径的既有冲突

| 既有口径 | 出处 | 与本次需求的关系 |
|---|---|---|
| "豁免铁律：输入框/密码窗永不透明；**悬浮球**、JOptionPane、JFileChooser/JColorChooser 不贴图" | `documents/交接说明.md:39` | 若按**口径丙**实现即违反该铁律；按甲/乙实现则需把铁律改写为"悬浮球不参与**窗口整面背景贴图**，但其**球体自绘皮肤**另属功能项" |
| 自动装配按窗口类名映射，未映射即豁免；悬浮球不在映射表 | `src/com/randomnamepicker/theme/BackdropManager.java:59,100-124` | 同上；本次**不建议**把 `FloatingBall` 加进 `categoryOf` |
| 装配引擎只接受 `JFrame/JDialog` | `src/com/randomnamepicker/theme/BackdropManager.java:129-131` | 悬浮球是 `JWindow`（`src/com/randomnamepicker/floating/FloatingBall.java:22`），本就被引擎拒之门外；保持这一限制反而更安全 |
| "整窗皮肤级沉浸（T3 自绘 L&F）未做，需另立项" | `documents/交接说明.md:76` | 本次球皮属"单组件自绘皮肤"，不等于 T3，但需在文档里把两者边界写清，避免被理解为主题引擎扩权 |

### 2.2 插件现有扩展面（能拿到什么 / 拿不到什么）

**能拿到**（公开 API，`plugin/HostApi.java:6-14`）：

- 9 个 `UiZone`（三类菜单 + 六个窗口按钮区）——**但没有任何"渲染/皮肤/绘制"槽位**（`plugin/UiZone.java:12-31`）。
- 宿主事件 9 类：`PLUGINS_CHANGED / SCHEME_CHANGED / MODE_CHANGED / PICK_STARTED / PICK_FINISHED / LOCK_CHANGED / BALL_SHOWN / BALL_HIDDEN / BALL_MOVED`（`plugin/HostEvent.java:21-40`）。
- `ModeHandler` 契约：`getModeId/getDisplayName/canPick/nextCandidate()/handleButton1Click/2Click/getButton1Text/2Text` + 新增 `getContextMenuItems()`（默认空）（`mode/ModeHandler.java:64-94`）。候选被限定为**纯字符串**。
- 几何只读查询 + `BALL_MOVED`（约 10 次/秒节流）替代轮询（`插件开发文档.md:717,721-730`）。

**拿不到**（明确非公开面）：

- `FloatingBall`、`NamePickerApp`、`ConfigManager`、`PasswordManager`、`theme` 包全部属"宿主内部、不承诺兼容"（`plugin/HostApi.java:15-17`、`插件开发文档.md:85,684-689`）。
- `PluginContext` 不提供球窗句柄、不提供"当前模式 Handler"、不提供"当前抽取的呈现钩子"（`plugin/PluginContext.java:31-99`）。
- 红线明示："**依赖宿主内部类/私有字段 = 破坏版本兼容承诺**"（`插件开发文档.md:619`）；对宿主窗口"仅允许 `instanceof`/几何观察做识别（灰色地带）"（`插件开发文档.md:560`）。
- 打包禁令已强制：jar 内出现 `com/randomnamepicker/` 前缀 `.class` 条目 → 整 jar 拒载 `BUNDLED_HOST_CLASS`（`plugin/PluginManager.java:601-605`；`插件开发文档.md:693-694`）。

**两个必须点名的既有实现缺陷**（球皮若复用这套渲染会被直接放大）：

1. `WindowBackdrop.IMAGE_CACHE` 是**静态无界** `HashMap`，键为绝对路径，**无淘汰**（`theme/WindowBackdrop.java:24,41-60`）→ 导入多张大图后内存只增不减；球窗每 100ms 重绘（`FloatingBall.java:241-249`）会让这条路径的代价显著高于其它窗口。
2. `ImageIO.read` 位于 `paintComponent` 调用链上（`theme/WindowBackdrop.java:68` → `:41-60`）：**首次绘制在 EDT 内解码整图**，且每帧按 `Graphics2D` 插值缩放（`:148`）。对普通窗口是"首帧卡一下"，对悬浮球（10Hz 常驻重绘 + 动画帧）就是持续开销。→ 球皮必须改成**预解码 + 预缩放到球像素尺寸 + 按尺寸/DPI 失效重建**。

### 2.4 抽奖（滚停）引擎现状

| `PICK_FINISHED` 在自停回调里派发，`result = rp.getLastValue()`（未截断原文） | `FloatingBall.java:331-342` | 若动画延长"视觉定格"，事件会**早于**视觉定格 → 音效/联动插件会提前触发（语义需明确定义） |

### 2.5 三处天花板（本次需求的根因）

1. **绘制天花板**：球体绘制是私有内部类里的硬编码颜色，无任何皮肤解析入口（`FloatingBall.java:76-92`）——换皮必须改这里，或从外部"盖住"它。
2. **呈现天花板**：滚停引擎的"显示"被抽象成 `Consumer<String>`（`RollingPicker.java:49-56`）——动画插件化必须把这一层升级为可替换的呈现对象。
3. **槽位天花板**：`UiZone` 只有"动作"语义，没有"渲染/皮肤/动画"语义（`plugin/UiZone.java:12-31`；改进建议 `documents/插件体系改进建议.md:178-185` 的 P1-5 已指出同一缺口）。

## 3. 方案 A：不改源码、纯插件能否实现？

### 3.1 路线枚举

| 路线 | 做法 | 依赖 |
|---|---|---|
| **A-a 组件蒙皮（窗内覆盖）** | 用 `Window.getWindows()` 找到可见球窗 → 沿组件树定位球窗内容层 → 往同一位置 `add` 一个自绘 JComponent 并用 `setComponentZOrder(comp,0)` 顶到最上 → 自绘照片球；再对宿主 `JLabel` 挂 `PropertyChangeListener("text")` 镜像滚动文本 | 纯 AWT/Swing 公有 API；识别球窗可只靠 `getClass().getSimpleName()`，**可做到零 import 宿主内部类** |
| **A-b 独立叠加窗口** | 自建 `JWindow`（照片球）用 `BALL_SHOWN/BALL_MOVED` 与宿主球同步位置，盖在宿主球上；用 `Component.dispatchEvent` 合成双击事件触发宿主抽取 | 公有 API + `dispatchEvent`（公有） |
| **A-c 反射替换** | 反射拿 `FloatingBall.displayLabel/ballPanel` 私有字段，把球窗内容层整体换成插件自绘容器 | 反射，明确越过红线（`插件开发文档.md:619`） |
| **A-d 只做配置不动球** | 插件只提供"球皮配置/图库/预览"UI（`FLOATING_BALL_MENU` + `SETTINGS_WINDOW` 动作），把用户选的照片存到插件自有目录，**贴图仍由用户手配宿主主题**（无球皮功能） | 完全合规，但**不满足需求** |

### 3.2 逐路线可行性判定

| 路线 | 球皮照片化 | 动画逐帧定制 | 拖动/双击保持 | 合规性 | 判定 |
|---|---|---|---|---|---|
| A-a 组件蒙皮 | 可行（`setComponentZOrder` 可盖住硬编码蓝圆） | **半可行**：只能把 1 秒滚动期间的文本变化当成"帧信号"自绘（20 帧/秒），无法改时长/节奏，无法在引擎层面"定格" | **破坏**：覆盖层会吞掉鼠标事件（监听在 `displayLabel`：`FloatingBall.java:112-116`），必须插件自己重实现拖动与双击语义 | 灰区边缘（结构化依赖宿主窗口组件树，超出文档允许的"instanceof/几何观察"） | 仅可作演示 |
| A-b 叠加窗口 | 可行 | 可行（自有窗口内任意动画） | **破坏**：真实事件落在插件窗口上，宿主球收不到；且宿主 100ms `toFront()`（`FloatingBall.java:244-249`）会与插件窗口**抢 z 序 → 闪烁** | 与"正计时子球"同族灰区 | 仅可作演示 |

### 3.5 方案 A 结论

- **技术上"能做出样子"**：找到球窗 → 覆盖一层自绘照片 → 镜像文本，静态球皮与"整段伪动画"都能跑起来；识别球窗甚至可以不 import 宿主内部类。
- **工程上不可交付**：输入交互（拖动/双击/右键）必须由插件重造并与宿主语义对齐；z 序、重绘、半径变更、球窗重建、与既有灰区插件互扰等一堆边界要自己兜；且一旦将来宿主做球皮/动画功能，这套蒙皮会与宿主功能叠加打架。
- **抽奖动画插件化在 A 下不成立**：核心瓶颈是呈现层被抽象为 `Consumer<String>`，插件没有任何"帧/定格/时长"话语权，只能在外层遮罩，**不是插件化，是覆盖**。
- **建议定位**：A 仅作为"不改源码的临时演示/个人自用"路径，**不作为正式交付**；若必须走 A，须同时接受"交互需重造、宿主升级可能失效、无热插拔"三项前置条件，并在插件文档里如实标注为灰区实现。

## 4. 方案 B：改动源码的实现路径

### 4.1 总体架构（分层）


**刚性设计原则（写进实现约束）**：

1. **取样与播放解耦**：结果永远由宿主（模式 Handler 的第 N 次候选）确定；皮肤与动画**只接收**结果，没有任何写入/改写结果的通道。
2. **零配置保真**：无球皮配置时，球体绘制必须与现版逐像素等价（默认路径 = 现有蓝圆代码路径）。
3. **单一帧驱动**：动画帧、球体重绘、文本刷新共用**一个** EDT Timer，避免"宿主 keepTop 100ms + 动画 Timer"两套节奏互相触发重绘（`FloatingBall.java:241-249` 目前每 100ms 无条件 `repaint()`）。
4. **插件渲染可熔断**：异常/超时/超预算 → 本次帧跳过、连续失败 → 停用该动画并回退默认呈现，只记日志。
5. **默认蓝球与默认文字动画永不删除**：任何插件失效路径都必须能落回默认。

```java
    /** 绘制球体（EDT，必须轻量；绘制须限制在 0,0,w,h 内；须开抗锯齿）。 */

    /** 可选：自绘球上文字；返回 false（默认）= 交回宿主默认文字绘制。 */
    default boolean paintText(java.awt.Graphics2D g, int w, int h, BallPaintState state) { return false; }
}

public interface RollPresenterFactory {
```

### 4.5 关键实现细节与坑（B 方案内部技术风险）

| # | 细节 | 坑 | 建议做法 |
|---|---|---|---|
| D-1 | 照片缩放 | 在 `paint` 里对原图做 `drawImage` 缩放（现 `WindowBackdrop.java:148` 的做法）在大照片/10Hz 重绘下昂贵 | 预缩放到球像素尺寸（含 DPI 系数）后缓存，`paint` 只做 `drawImage(缓存, 0,0)`；尺寸/照片/DPI 变化时失效重建 |
| D-2 | 圆形裁切 | `fillOval` 换成 `Ellipse2D` 裁切 + 抗锯齿，边缘会出现半透明锯齿 | 用 `TexturePaint` 或"先画到 ARGB 缓存图再 drawImage"，避免每帧 clip 抖动 |
| D-3 | 透明度语义 | 现 `ballOpacity` 是**颜色 alpha**（`FloatingBall.java:87`），照片球需要**图层 alpha** | 改为 `AlphaComposite` 作用于球体图层；保持滑杆数值-观感连续；老配置值照常可用 |
| D-4 | 窗口透明能力 | 现已在用 `setBackground(0,0,0,0)`（`:45`）；照片球会把"圆外四角是否真透明"暴露得更明显 | 启动时检查 `GraphicsEnvironment.isTranslucencySupported(PERPIXEL_TRANSLUCENT)`，不支持则球皮降级为"方形+不透明底"或禁用球皮，并在设置窗给出说明；复用现有创建失败提示路径（`NamePickerApp.java:699-702`） |
| D-5 | 点击热区 | 球窗是矩形，圆形绘制只影响视觉；现状 `displayLabel` 满铺 → 四角空白也响应拖动/双击 | 保持现状（简单、与现行为一致）；若要做异形热区需 `setShape(Shape)`（Windows 支持但会带来拖动/临时区/合成器兼容问题）→ 列为**可选 P4**，默认不做 |
| D-6 | 文字与照片对比 | 白字在亮照片上不可读 | 默认"白字 + 1px 深色描边"；可选"自动压暗"（按照片亮度给 mask 下限）；可选自定义文字颜色 |
| D-7 | 尺寸/半屏/多屏 | 半径改变 → 球窗与字体尺寸变化 → 缓存必须失效；多屏混合 DPI 下逻辑像素 ≠ 物理像素 | 缓存键纳入 `GraphicsConfiguration` 的 transform 缩放；`componentResized`/`BALL_MOVED` 时校验尺寸并失效 |
| D-8 | 与计时子球联动 | 子球尺寸 = 宿主球宽 × 0.55（clamp 36–60）、方位按球 bounds 推导（`FloatingBallTracker.java:258-300`） | 口径乙（底座）会改变球窗尺寸 → 子球尺寸/方位随之漂移；建议优先口径甲；若做乙，需把"球体直径"与"窗口尺寸"分离并通知既有插件 |
| D-9 | 事件风暴 | 动画提升帧率会放大 `BALL_MOVED` 上报与重绘（现 100ms 一次已含 `repaint`） | 帧驱动与几何上报解耦：几何仍按 100ms 比对上报（保持现有节流口径，`FloatingBall.java:256-263`） |
| D-10 | 插件做重活 | 帧回调在 EDT（`PluginManager.java:479-507` 的派发口径） | 帧预算 + 连续失败熔断（B3-7）；插件侧要求"预准备在后台、帧内只绘制" |

## 6. 改进路径

### 6.1 路径一：只求功能、不求插件化（推荐先做）

**B1 宿主内建球皮** → 交付"照片球皮 + 导入/裁切/遮罩/形状 + 文字可读 + 保真回退"。
同时做两件低成本、必须先做的"口径工程"：

1. **文档口径修订**（零代码）：在《交接说明》《插件开发文档》中明确"悬浮球不参与窗口整面背景贴图，但支持**球体自绘皮肤**"，并把 `theme/floating` 的边界写清（`BackdropManager` 的 `JFrame/JDialog` 限制保持不动）。
2. **图库与缓存治理**：复用 `ThemeStore` 图库；新增"按尺寸预缩放 + 有界缓存"，顺带修掉 `WindowBackdrop.IMAGE_CACHE` 无界问题。

**验收要点**：无配置时像素级等价现版；照片球在 100%/125%/150% 缩放与双屏下位置/裁切正确；半径滑杆变化后缓存正确失效；拖动/双击/右键菜单行为与现版一致。

### 6.2 路径二：要生态（完整需求，分三步）

```text
B1 宿主内建球皮  →  B2 呈现层抽象(RollPresenter + 内置动画)  →  B3 插件 SPI(球皮/动画) + 文档 + 示例
   (观感落地)          (动画能力落地、非插件化)                    (真正的"插件化"，API 级别 2→3)
```

**门槛条件（建议在 B3 立项时明确写入任务书）**：

- 出现**真实第三方**或**内生多套动画**需求（≥3 套动画/皮肤），否则 B3 的收益不足以覆盖性能、争抢、兼容三类风险；
- 已有帧预算/熔断/降级机制的实现与验证（R-12、R-11 的兜底）；
- 已具备至少一个可复用示例（`examples/plugin-ball-skin/`）与文档章节。

### 6.3 路径三：坚决不改源码（受限交付）

按 §3 结论，只交付**能保证的部分**并明确不承诺的部分：

| 交付 | 不承诺 |
|---|---|
| 插件自有的"球皮/动画设置"窗口（`FLOATING_BALL_MENU` + `SETTINGS_WINDOW` 动作） | 不保证能真正改变宿主球的外观（需依赖覆盖式灰区实现） |
| 图库/导入/裁切/预览 + 自持配置（`data/<插件名>/`） | 不进入宿主设置窗体系，两套配置源并存 |
| 覆盖式球皮 + 遮罩式伪动画（演示级） | 不承诺拖动/双击/右键行为等价；不承诺宿主升级后可用；不承诺热插拔 |

**前置条件（若走这条路，必须在插件 README 与本分析文档中如实标注）**：交互需重造、宿主升级可能失效、无热插拔、可能与其他灰区插件互扰。

### 6.4 不建议的路径（及理由）

| 路径 | 不建议的理由 |
|---|---|
| 反射替换宿主球窗内容层（A-c） | 明确越过插件红线（`插件开发文档.md:619`），宿主改版必碎；且会与将来宿主内建球皮功能正面冲突 |
| 把 `FloatingBall` 加进 `BackdropManager.categoryOf`，用"窗口背景贴图"实现球皮（口径丙） | 出"方块球"；破坏"悬浮球不贴图"铁律（`documents/交接说明.md:39`）；还会把 `WindowBackdrop` 每帧解码/缩放的开销注入 10Hz 重绘的球窗（R-07） |
| 让动画插件接管 `Timer`/候选节奏 | 直接击穿"结果=第 20 次候选"与日志/事件口径（R-10），属功能正确性风险，不是体验问题 |
| 在 B3 前先做"插件注册皮肤就立即生效、无需用户选择" | 多插件争抢 → 不确定行为（R-13）；"最后加载者胜"对用户不可解释 |
| 用 `setShape` 做异形球 + 精确热区（作为必做项） | 收益（四角可点）远小于风险（拖动/合成器/多屏兼容），建议列为可选 P4 |
