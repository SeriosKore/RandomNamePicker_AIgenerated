# 正计时子球开发方案

> 面向 AI 助手的插件开发方案书（本阶段**只出方案、不写代码**）。
> 目标宿主：RandomNamePicker（Java Swing，`com.randomnamepicker`，Stage3 插件化已完成）。
> 硬约束：**不改动、不依赖改动任何现有宿主代码**；产物为独立插件 jar，部署到运行目录 `plugins/`。

---

## 0. 需求复述（与用户确认后的最终口径）

在“抽取球”（即宿主悬浮球 `FloatingBall`，圆球窗口，默认显示“抽取”）上增加一个**正计时子球**：

| # | 触发者 | 动作 | 效果 |
|---|---|---|---|
| 1 | 悬浮球 | 单击（非拖动、非双击序列） | 子球**冒出**并自动开始正计时（就绪 00:00 起步） |
| 2 | 悬浮球 | 再次单击 | 子球**收回**并暂停计时（读数保留） |
| 3 | 悬浮球 | 再单击 | 子球重新冒出并继续计时 |
| 4 | 子球 | 单击 | 运行中→暂停；暂停中→继续（不收回） |
| 5 | 子球 | 双击（**仅暂停态有效**） | 计时归零为 00:00 并收回子球 |
| 6 | 悬浮球 | 双击 | **不变**：宿主随机抽取 |
| 7 | 悬浮球 | 拖动 | **不变**：宿主移动悬浮球，子球跟随 |
| 8 | 悬浮球 | 右键菜单 | **不变**：宿主菜单；追加本插件菜单项 |

**冒出方向规则（已确认）**：以悬浮球当前所在屏幕（其几何中心所在显示器）的垂直中线为界——
悬浮球位于屏幕**下半部分**时，子球从悬浮球**正上方**冒出；位于**上半部分**时，从**正下方**冒出。目的：子球始终朝远离屏幕上下边缘的方向展开，避免出屏。

**保持事项（已确认）**：悬浮球原有全部能力（拖动、双击抽取、右键菜单、置顶常驻）行为不变；
子球为插件自有的独立小球，仅承担计时，不参与抽取、不遮挡悬浮球可点击区。

## 1. 可行性结论（先讲清楚为什么必须这么做）

### 1.1 宿主留给插件的钩子

Stage3 插件 API（`PluginContext`；宿主 2026-09-05 起为 **UI 槽一期**版）提供的注册能力：

1. `registerModeHandler(ModeHandler)` —— 注册新模式；
2. `addUiAction(UiZone zone, String title, ActionListener)` —— 按 UI 区域注册动作（暂存语义）；
   - 一期区域：`UiZone.MAIN_MENU / TRAY_MENU / FLOATING_BALL_MENU / SETTINGS_WINDOW`
     （`SETTINGS_WINDOW` = 设置窗“插件”按钮区，宿主 `SettingsWindow` 在列表末渲染；无动作时返回 null 不渲染）；
   - zone 为 null = 插件缺陷 → 宿主整 jar 原子拒载（D8 严格失败语义）；title/action 空则忽略；
   - 旧 `addMainMenuAction / addTrayMenuAction / addFloatingBallMenuAction` 现为等价便捷默认方法（委托上 API）；
3. 数据/日志服务访问（NameManager / SchemeManager / DataManager / LogManager / ModeHost / log）；
4. `Plugin` 生命周期：`onLoad`（后台加载线程、暂存语义）与 `onUnload`（退出时）。

宿主侧 UI 槽由 `ui.PluginUiSupport.createZonePanel(zone)` 渲染：按 zone 从 PluginManager 取已提交动作生成
按钮（点击经 `runMenuActionSafely` 防御执行），空 zone 返回 null。**SettingsWindow 每次实例化时读取一次**
已提交插件动作——先于插件提交打开的设置窗需关闭重开才出现按钮（与悬浮球右键菜单同源语义，文档明示）。

**API 中仍没有**：悬浮球实例引用、悬浮球几何查询、悬浮球单击/双击事件钩子、向悬浮球窗口叠加子视图的能力。
悬浮球本体鼠标监听（按下即拖、双击抽取）仍是宿主内部代码，插件拿不到 `displayLabel`，也无法在悬浮球上
“追加”单击监听（鼠标事件只派发给命中的最深组件）——因此“单击悬浮球本体=冒出/收回”仍走 §1.2 通路 A+B。

### 1.2 因此采用两条“宿主无关”通路，实现零宿主改动

- **通路 A —— 全局 AWT 鼠标监听（观察式，不拦截）**：
  插件用 `Toolkit.getDefaultToolkit().addAWTEventListener(...)` 观察 `MOUSE_PRESSED/MOUSE_RELEASED/MOUSE_CLICKED/MOUSE_DRAGGED`。
  当事件的目标组件位于**当前可见悬浮球窗口内**且为左键时，插件据此实现“单击悬浮球=冒出/收回”；
  插件**从不 consume 事件**，只观察，故悬浮球自身拖动、双击抽取逻辑完全不受影响。
- **通路 B —— 悬浮球几何追踪**：
  插件用 EDT 上的 `javax.swing.Timer`（约 50–100ms）轮询 `Window.getWindows()`，
  找到当前可见的 `FloatingBall` 实例（宿主每次开关都会 dispose 后重建，需持续重探测），
  读取其屏幕位置与尺寸 → 计算子球应处位置并搬移/隐藏 → 保证“子球跟随悬浮球、悬浮球消失子球即隐”。

> 说明：原拟“宿主钩子式”（在 FloatingBall 源码加一行回调）虽最直接，但与“不改任何现有代码”冲突，
> 已否决。通路 A+B 在**不改宿主一行代码**的前提下达成完全相同的用户体验。

### 1.3 单击与双击/拖动的区分（关键技术点）

悬浮球双击=抽取是宿主的既有行为，其判定发生在第二次 mousePressed（`clickCount==2`）。
而一次双击序列中，第一次点击对监听者而言与单击**完全无法在事件当下区分**（都是 `clickCount==1`）。
处置方案（对悬浮球与子球统一采用“延迟单击、双击取消”）：

1. 捕获悬浮球上的 `clickCount==1` 单击事件后，**不立即执行**，而是启动一个可重置的延迟定时器
   （时长取 `Toolkit.getDesktopProperty("awt.multiClickInterval")`，典型 500ms）；
2. 延迟窗口内若到来 `clickCount==2`（双击）→ 取消挂起的单击动作，让宿主双击抽取照常执行；
3. 按下期间**只要出现任一 MOUSE_DRAGGED 即取消**挂起的单击动作（宿主 1px 即移动窗口，**不设位移阈值**；取消与否与宿主窗口是否真正发生位移无关，目的仅是防止“误把拖动当单击”）；
4. 延迟到期仍无冲突 → 才执行“单击悬浮球=冒出/收回”。
5. 已知代价：单击响应有约 0.2–0.5s 可感知延迟（双击防误触的标准代价），子球与悬浮球一致，可接受并在文档明示。

双击“随机抽取”按下瞬间即触发（宿主逻辑不变）；插件侧挂起的单击被取消，不会出现“抽完又冒出子球”的副作用。

## 2. 状态机设计（最终口径）

### 2.1 两个正交状态

- 子球形态状态：`HIDDEN（收起）` ↔ `VISIBLE（展开）`
- 计时状态：`READY（就绪，读数为 00:00）` / `RUNNING（运行）` / `PAUSED（暂停，读数保留）`

### 2.2 迁移表

| 当前形态 | 当前计时 | 事件 | 新形态 | 新计时 | 备注 |
|---|---|---|---|---|---|
| HIDDEN | READY | 单击悬浮球 | VISIBLE | RUNNING | 首次冒出=从 00:00 开始正计时 |
| HIDDEN | PAUSED（保留读数） | 单击悬浮球 | VISIBLE | RUNNING | 重新冒出=继续 |
| VISIBLE | RUNNING | 单击悬浮球 | HIDDEN | PAUSED | 收回=暂停，读数保留 |
| VISIBLE | PAUSED | 单击悬浮球 | HIDDEN | PAUSED | 收回，读数保留 |
| VISIBLE | RUNNING | 单击子球 | VISIBLE | PAUSED | 子球单击=暂停 |
| VISIBLE | PAUSED | 单击子球 | VISIBLE | RUNNING | 子球单击=继续 |
| VISIBLE | PAUSED | 双击子球 | HIDDEN | READY | 归零并收回（用户确认的“双击重置”） |
| VISIBLE | RUNNING | 双击子球 | VISIBLE | RUNNING | 双击仅在暂停态有效；运行态双击忽略（防误清零） |
| VISIBLE | READY | 单击子球 | VISIBLE | RUNNING | 例外补全：展开而未计时时单击=开始（防御分支） |
| VISIBLE | READY | 单击悬浮球 | HIDDEN | READY | 防御分支：收回（正常流程不可达；菜单“冒出/收回”同口径） |
| 任意 | 任意 | 悬浮球双击（宿主抽取） | 不变 | 不变 | 宿主行为，插件仅取消挂起单击 |
| 任意 | 任意 | 悬浮球拖动 | 跟随 | 不变 | 子球跟随悬浮球位移 |
| 任意 | 任意 | 悬浮球被关闭/隐藏/dispose | HIDDEN | RUNNING→PAUSED | 子球随之隐藏并暂停保留读数；悬浮球重现后不自动冒出 |

**菜单动作与状态表对齐（评审 P2 定稿）**——菜单不引入新状态，全部映射到上表同口径迁移：

1. **“计时子球：冒出/收回” ≡ “单击悬浮球”**：同一动作、同一迁移表，仅执行路径不同（菜单点击 vs 本体单击）：
   - `HIDDEN + READY` → **冒出并置 RUNNING，自 00:00 起**（READY 从未计时态的冒出的初始态定稿，与“首次单击悬浮球”一致）；
   - `HIDDEN + PAUSED` → 冒出并继续（RUNNING）；
   - `VISIBLE + RUNNING` → **收回=暂停**（读数保留；表内已有该行语义，此处显式声明菜单同样适用）；
   - `VISIBLE + PAUSED` → 收回（读数保留）；
   - `VISIBLE + READY`（防御）→ 收回至 HIDDEN+READY。
2. **“计时归零”最终落点固定为 `HIDDEN + READY`**（读数 00:00 且收起，与“暂停态双击子球重置”完全一致）：
   - `VISIBLE + RUNNING` → **先暂停 → 清零 → 收回**（归零伴随收回）；
   - `VISIBLE + PAUSED` → 清零并收回（≡ 双击重置）；
   - `VISIBLE + READY`（防御）→ 收回（本就 00:00）；
   - `HIDDEN + PAUSED` → 清零，保持收起；
   - `HIDDEN + READY` → 无操作（已 00:00 且收起）。

### 2.3 计时实现要点

- **不靠 tick 计数累加**，避免丢帧漂移：内部维护 `accumulatedMs`（已累计时长）与 `resumeBase`（本次启动的系统时间戳），
  显示值 = `accumulatedMs + (RUNNING ? now - resumeBase : 0)`；tick 仅驱动刷新（建议 200ms 刷新，秒级显示）。
- 显示格式：`MM:SS`（如 00:00）；累计 ≥1 小时自动进位为 `H:MM:SS`。
- 重置：`accumulatedMs = 0`，回 READY，显示 00:00。

### 2.4 子球视觉与行为

- 子球 = 插件自有的无边框、透明、**圆形** `JWindow`（置顶、不可获得键盘焦点 `setFocusableWindowState(false)`，
  避免抢走主程序输入焦点），自绘圆形底色 + 居中时间文本，字号随球径缩放。
- 尺寸：默认取悬浮球直径的约 0.55 倍，夹在 36–60px（常量可调）。
- 状态配色（常量可调）：READY=灰蓝、RUNNING=绿、PAUSED=橙，文字白色。
- 与悬浮球几何关系：水平中心对齐；垂直方向按 §0 规则置于悬浮球上方（gap≈6px）或下方；整体按所在屏幕边界 clamp，防出屏。
- 跟随：几何追踪轮询期间若悬浮球存在且子球 VISIBLE → 重算位置并搬移；同时 `toFront()` 维持置顶层级。
- 双击/单击判定与悬浮球同法（§1.3 延迟-取消）。

## 3. 插件包结构设计（零宿主改动的实现切分）

建议在 `examples/plugin-timer/` 下新建源码目录（沿袭 `examples/plugin-example/` 的工程习惯），
**jar 内只含插件自身类，禁止打包 `com/randomnamepicker/**`**：

| 类（示意职责） | 职责 |
|---|---|
| `CountUpTimerPlugin`（实现 `Plugin`） | 入口。`getName()`=“正计时子球”、`getVersion()`=“1.0”。`onLoad`：注册设置窗按钮 `addUiAction(UiZone.SETTINGS_WINDOW, "计时子球", …)` + 三类菜单动作（冒出/收回、归零），并调度 EDT 初始化（建 Config/Tracker、装全局 AWT 监听、启轮询、预建隐藏子球）；`onUnload`：完整清理。所有 UI 严格 EDT（onLoad 在后台线程） |
| `FloatingBallTracker` | 通路 A+B 实现者 + 主题持有者：`Window.getWindows()` 轮询定位可见 `FloatingBall`；全局 AWT 监听过滤“命中悬浮球窗口的左键事件”，做单击延迟-取消（防拖动/双击误触）后翻转子球形态；按 Config 的尺寸策略（自动×0.55 夹 36–60 / 固定直径）与配色驱动子球 |
| `TimerBall` | 子球窗口本体：圆形自绘 + 时间刷新 tick + 自身单击/双击状态机（§2.2）；配色/尺寸读自共享 Config（可实时换肤） |
| `TimerBallConfig`（新增） | 子球外观配置模型：默认值=现行代码常量；读写 `data/timerball_plugin.properties`（合并式、损坏回退默认）；暴露尺寸策略与三态颜色 |
| `TimerBallSettingsDialog`（新增） | “计时子球设置”对话框：由设置窗“插件”区按钮打开；控件绑定 Config，修改即持久化 + 实时应用（含“恢复默认”） |
| `BUILD.txt` / `BUILD.bat` | 编译打包与安装说明（见 §6） |

> 可省略点：不注册插件模式（下拉框无新增项；菜单/按钮与“名称 版本”只读项仍会出现于“插件”菜单）。

### 3.1 入口（按钮 + 菜单，主交互仍是“单击悬浮球本体”）

- **设置窗“插件”区按钮（二期新增，宿主 UI 槽一期）**：`ctx.addUiAction(UiZone.SETTINGS_WINDOW, "计时子球", e -> …)` →
  打开“计时子球设置”对话框（§3.3）。宿主在 SettingsWindow 实例化时渲染；**先于插件提交打开的设置窗需重开一次**。
- 主窗“插件”菜单 + 托盘菜单 + 悬浮球右键菜单：`计时子球：冒出/收回`（与单击悬浮球同一动作）、`计时归零`，
  分隔线后只读 `正计时子球 1.0`（只读项由宿主自动附于“插件”菜单）。
- 悬浮球右键菜单/设置窗按钮均为宿主在实例化时读取已提交插件动作：安装后需重开一次悬浮球/设置窗（宿主机制）。
- 悬浮球不存在时点“冒出/收回”→ 仅提示“请先打开悬浮球”。

### 3.2 生命周期与清理（务必完整，避免泄漏）

- 全局 AWT 监听：`onLoad`（EDT 上）注册；`onUnload` 一律 `removeAWTEventListener`。即使 jar 因其它候选被整包拒载，回滚路径也会对已 onLoad 者补 onUnload，本插件按此契约清理即可。
- 轮询定时器：onUnload 停止；子球 JWindow：onUnload dispose（程序退出经 `PluginManager.shutdown()` → `onUnload`）。
- 设置对话框为瞬态（关闭即释放），不持有跨会话引用。
- 日志：开始/暂停/继续/归零/冒出/收回/设置变更等关键动作经 `ctx.log`/`LogManager.log` 落 `log/Modifylog.txt`
  （操作码：`TIMER_START/TIMER_PAUSE/TIMER_RESUME/TIMER_RESET/TIMER_BALL_SHOW/TIMER_BALL_HIDE/TIMER_CONFIG`，与宿主既有码无冲突）。
- 退出时插件动作/监听/定时器全部回收，不残留。

### 3.3 子球外观设置对话框（设置窗“插件”区“计时子球”按钮 → 弹出）

- **入口归属**：宿主设置窗“插件”按钮区；按钮 = 每个已提交插件一个（本插件 1 个，标题“计时子球”）。
- **对话框形态**：以按钮事件源所在 Window（= SettingsWindow）为 owner 的模态 JDialog（标题“计时子球设置”），
  与宿主其它对话框一致；关闭即弃。
- **设置项与默认值（默认 = 现行代码常量，全部可调）**：

| 设置项 | 控件 | 默认 | 键 |
|---|---|---|---|
| 尺寸模式 | 单选：随悬浮球自动 / 固定直径 | 自动 | `sizeMode` |
| 固定直径（手动模式） | 滑杆 30–90px | 44px | `fixedDiameter` |
| 就绪色 | 色块按钮 → JColorChooser | 灰蓝 0x7086A6 | `colorReady` |
| 运行色 | 色块按钮 → JColorChooser | 绿 0x2E8B57 | `colorRunning` |
| 暂停色 | 色块按钮 → JColorChooser | 橙 0xE08A2E | `colorPaused` |
| 与悬浮球间距 | 滑杆 4–20px | 6px | `gapPx` |
| 恢复默认 | 按钮 | — | — |

- **生效与持久化**：修改即实时生效（已显示的计时子球立即变色/变尺寸/变间距——模态只挡点击不挡重绘）并
  合并写回 `data/timerball_plugin.properties`；重启后加载。配置文件为**插件自持**（不触碰宿主
  `data/config.properties`，规避宿主私有键管理/写回策略耦合）。
- **锁门控对齐**：与宿主“悬浮球外观”一致属外观类，不设全局锁门控（宿主外观滑杆亦无锁）。
- **色彩损坏防护**：十六进制解析失败回退默认。

## 4. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 悬浮球每次开关都 dispose + 重建（宿主 `showFloatingBall` 逻辑） | 轮询**持续重探测**：以“isDisplayable && 可见”为准，旧引用失效即换新；子球形态状态跨实例保留 |
| 双击抽取与单击冒出混淆 | §1.3 延迟-取消机制；宿主双击抽取发生在第二次 press，插件挂起单击被取消，两者互不触发 |
| 按下后拖动被误判为单击 | 按下期间出现**任一 MOUSE_DRAGGED 即取消**挂起单击（**不设位移阈值**，与宿主窗口是否真正移动无关；与 §1.3 第 3 条口径一致） |
| 子球被其它置顶窗口遮挡 / 与悬浮球层级抖动 | 子球 `setAlwaysOnTop(true)`，随追踪轮询 `toFront()`；悬浮球自身 100ms `toFront` 与其互不干扰（子球与悬浮球不重叠：gap 布局 + 方向规则） |
| 多显示器边缘、子球冒出出屏 | 以悬浮球几何中心所在 `GraphicsDevice` 为“当前屏幕”，冒出方向按该屏中线判定并做边界 clamp |
| 全局 AWT 监听影响其它程序/宿主 | 纯观察不 consume；仅对“祖先链含悬浮球窗口”的左键事件响应；`onUnload` 必卸 |
| 插件代码引用宿主类（FloatingBall 等）的耦合脆弱性 | 宿主 parent-first 提供 API，运行时可用；若未来宿主改动悬浮球实现（如改绘制方式），仅影响本插件定位/点击归属判定，方案留有菜单回退入口 |
| EDT/后台线程违规 | 全部 Swing 操作收敛于 EDT（onLoad 内一律 invokeLater / 定时器天然 EDT） |
| 子球抢键盘焦点 | `setFocusableWindowState(false)` |
| 设置窗按钮依赖宿主新 UI 槽（`UiZone.SETTINGS_WINDOW` + `PluginUiSupport`） | 宿主（用户侧）已按“UI 槽一期”实现并重建 jar/out；插件仅 `onLoad` 里 `addUiAction` 注册，**零宿主改动**；若宿主为旧版（无该槽）则按钮不出现，其余功能与旧菜单入口不受影响 |
| 设置窗先于插件提交打开 → 按钮缺失 | 宿主机制：设置窗每次实例化时读取已提交插件动作（与悬浮球右键菜单同源）→ 关闭重开一次即出现；文档明示 |
| 设置对话框 owner / 模态 | 以按钮事件源所在 Window（即 SettingsWindow）为 owner 模态打开；关闭即弃，不残留引用 |
| 插件配置与宿主 config 冲突 | 自持 `data/timerball_plugin.properties`（不触碰 `data/config.properties`），合并式读写、损坏回退默认 |
| 悬浮球半径联动与手动尺寸并存 | 轮询中按 Config 尺寸策略解析实际直径（自动 = 悬浮球直径×0.55 夹 36–60；固定 = 滑杆值），设置变更实时重算 |

## 5. 明确不做（边界）

- 不改任何宿主代码与宿主行为；不做热插拔（装/卸插件需重启程序，宿主机制如此）；
- 不注册新模式、不介入主窗/悬浮球抽取流程、不读名单数据；
- 不做多计时器、不做倒计时、不做声音/通知；
- 悬浮球“隐藏/关闭”仅暂停并保留读数，不做自动重置。

## 6. 构建与部署（沿袭 plugin-example 模式）

```
1. 代码就位：examples/plugin-timer/ 下五个 .java（CountUpTimerPlugin / FloatingBallTracker / TimerBall / TimerBallConfig / TimerBallSettingsDialog，见 §3）。
2. 编译（以主工程 out 或主 jar 为 API 类路径）：
     javac -encoding UTF-8 -cp ../../out -d build examples/plugin-timer/*.java
   （若 out 过期：先 tools\build.bat 重新编译主工程——只重编宿主，不改其源码）
3. 打包：
     jar cf CountUpTimerBall.jar -C build .
4. 安装：把 CountUpTimerBall.jar 复制到运行目录 plugins/（与 jar/exe 同级；目录不存在会自动创建），重启程序。
5. 卸载：删除该 jar 后重启。
6. 预期日志：加载成功记 PLUGIN_LOADED；退出记 PLUGIN_UNLOADED；计时动作按 §3.2 记录。
```

> `ui.PluginUiSupport` / `SettingsWindow` 插件区），`out/` 与 `RandomNamePicker.jar` 已重建；
> 插件编译以新版 `out` 为 API 类路径。若宿主源码后续再变，先重编宿主（`tools\build.bat`，不涉源码修改）再编插件。
