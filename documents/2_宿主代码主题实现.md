# 2_宿主代码主题实现（工作流程报告）

> 前置文档：《背景主题插件开发方案.md》（报告 1，插件形态）。本报告回答：**若允许修改宿主代码，
> "各窗口照片背景主题"能做到哪一步**，并给出宿主侧工作流程（阶段/改动面/验收/风险）。
> 当前仅为方案报告，**不含代码改动**；宿主改动范围仅限"主题"功能相关，不触碰其它逻辑。

## 0. 结论速览（能做到哪一步）

| 能力 | 插件形态（报告1） | 宿主代码更新后 |
|---|---|---|
| 设置入口（设置窗） | 插件区按钮（间接） | **设置窗内建"背景主题"分节**（与半径/透明度并列，原生直达） |
| 背景生效时机 | 开窗后侦测装饰（可能闪烁 ≤1 帧） | **窗口构造即装配，无闪烁**（每窗一行接入或统一装配点） |
| 窗口变化（resize）联动 | 插件挂监听 | **宿主统一引擎**接管，稳定、集中清理 |
| 覆盖范围 | 仅"留白面板"透出，表格/控件区域不透 | **T1：全窗照片背景 + 表格/控件原生**；**T2（可选）：表格/文本区受控半透明化**；**T3（大改）：Look&Feel 级皮肤** |
| 图片/模式/裁剪/遮罩 | 插件自持 | 宿主内建（数据/设置/引擎归宿主） |
| 对插件生态 | 依赖 UI 槽 | 宿主原生；"正计时子球"等插件不受影响 |

**无论如何都做不到（即使改宿主源码）**：系统原生标题栏/边框贴图、托盘图标、OS 级文件对话框；
真"皮肤级全像素"需要自绘 Look&Feel（T3），成本与回归风险极高，默认不做。

**推荐目标 = T1（主）+ T2 作可选开关**：开窗即贴、resize 集中处理、遮罩保可读、表格等控件保持原生或按需半透明。

## 1. 宿主侧目标架构

新增宿主主题模块（建议包 `com.randomnamepicker.theme`）+ 少量既有文件接线：

| 宿主新类（示意） | 职责 |
|---|---|
| `Theme` / `WindowThemeStyle` | 主题数据模型：图片、适配模式（居中/适应/填充/拉伸/自由裁切）、归一化裁剪框、遮罩值、每类窗口映射 |
| `ThemeStore` | 持久化：`ConfigManager` 增键或 `data/theme.properties`；图片复制入库 `data/themes/images/` |
| `WindowBackdrop` | 自绘背景组件（缩放缓存 + 模式绘制 + 遮罩混合），置于内容层之下 |
| `BackdropManager` | 统一引擎：装配/拆卸、resize 与 shown/hidden 重排、透明化白名单策略（DFS 翻转并记录）、豁免清单、卸载还原 |
| `ThemeSettingsPanel` | 内建到 SettingsWindow 的"背景主题"分节（图库/全局与类别行/模式下拉/自由裁切预览/遮罩/恢复默认） |
| `WindowThemeSupport` | 静态装配入口：`install(Window w, String category)`；各窗口构造时一行调用 |

既有文件**接线面（最小化）**：主窗 `NamePickerApp` 与各对话框（`ConfigWindow / SchemeManagerDialog /
NumberPicker / SeatPicker / SettingsWindow / 密码类对话框`）构造尾部各加 1 行 `WindowThemeSupport.install(this, 类别)`；
`SettingsWindow` 布局加入"背景主题"分节；`ConfigManager`（如需入主配置）扩展键与 getter。
豁免不接线：`FloatingBall`、消息弹窗（默认）、JFileChooser/JColorChooser（宿主内不装配）。

> 装配方式取舍：**逐窗口一行接线**（改动 ~12 个文件各 1–2 行，换来开窗即贴零闪烁、语义明确）优于
> 全局 AWT 侦测（少改文件但开窗有瞬时原样帧）。推荐前者。

## 3. 渲染与"窗口变化图片调整"机制（宿主内实现更稳）

- 每窗口构造即：内容层下垫 `WindowBackdrop` → 按透明化白名单翻转容器（JPanel/JScrollPane/Box 等，
  按钮/表格/输入框默认保持原生，见 T1/T2）→ 挂 `ComponentListener`（resized/moved/shown/hidden → 缓存失效+重绘）。
- 缩放缓存按 `(窗口, 宽高, 图, 模式, 裁剪框)` 命中；自由裁切归一化 (x,y,w,h) 存于样式。
- **遮罩做在缩放图内**（半透明白混合，默认 40，滑杆 0–180）——不新增内容层之上的拦截层，不挡鼠标。
- 集中清理：窗口关闭/宿主退出统一拆卸还原，无泄漏。

## 5. 风险与回归关注

- 表格/文本控件透明化（若上 T2）最易出观感问题：需遮罩兜底 + 聚焦/选区高亮保可读，按开关灰度；
- 全窗贴图后各对话框按钮/文字对比度依赖遮罩滑杆，默认 40 + 可调；
- 宿主接线文件多，逐文件小改但回归面广 → 阶段 2/4 各做一次全窗口人工过检；
- 与插件生态：`PluginUiSupport`/`UiZone` 不动；计时子球插件正常运行；报告 1 的"背景主题插件"若宿主内建则被取代（可不再发布）。

## 7. 待拍板决策点

1. **架构归属**：A. 主题作为宿主内建功能（推荐，用户所问方向）　B. 宿主只做"背景槽+引擎"，图片/设置仍由插件提供；
2. **覆盖级别**：T1（表格等控件原生，推荐先做）　T1+T2（表格/文本受控半透明，工作量+回归 ↑）；
3. **设置与存储**：设置并入 SettingsWindow 原生分节 + 键入 `data/config.properties`（推荐）　或独立 `data/theme.properties`；
4. **自由裁切/遮罩默认**：沿用报告 1 已拍板（自由裁切=手动框；模式默认填充；遮罩默认 40）。
