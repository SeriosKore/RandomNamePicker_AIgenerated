# 插件接口文档（v1.1.0）

> 适用主程序：RandomNamePicker v1.1.0
> 面向对象：插件开发者 / 评阅人
> 配套教程见《插件开发文档.md》

## 1. 插件系统概述

主程序启动时自动扫描运行目录下 `extensions/*.jar`，读取每个 JAR 清单（MANIFEST.MF）中的 `Plugin-Class` 属性并实例化插件类，随后调用其 `onLoad(PluginContext)` 完成注册。**不需要修改主程序任何代码**即可扩展功能。

关键规则：

| 规则 | 说明 |
| --- | --- |
| 加载目录 | 程序运行目录下的 `extensions/`（不存在时自动创建） |
| 清单属性 | `Plugin-Class: <插件类全名>`（默认包写类名即可） |
| 类加载器 | 每个插件独立 `URLClassLoader`，插件间互不干扰 |
| 运行环境 | 与主程序同一 JVM、同一 Swing 事件线程，享有完整权限 |
| 异常隔离 | 插件加载/运行异常只记录到 `log/Modifylog.txt`，不影响主程序 |
| 卸载 | 程序退出前调用 `onUnload()`，随后关闭类加载器 |
| 安全提示 | 请仅加载可信来源的插件（插件与主程序权限相同） |

## 2. 核心接口

### 2.1 Plugin（插件必须实现）

```java
public interface Plugin {
    String getName();          // 插件名称（界面/日志展示）
    String getVersion();       // 版本号
    String getDescription();   // 功能描述
    void onLoad(PluginContext context);   // 加载时注册扩展点
    void onUnload();                       // 退出前释放资源
}
```

实现类必须有**无参构造方法**。

### 2.2 PluginContext（插件与主程序交互的唯一入口）

`onLoad` 收到的 `context` 提供以下能力：

#### ① 标准扩展点

| 方法 | 注入位置 | 触发时机 |
| --- | --- | --- |
| `registerMainMenuItem(text, action)` | 主窗口“插件”菜单 | 点击菜单项 |
| `registerMainButton(text, action)` | 主窗口底部插件按钮区 | 点击按钮 |
| `registerTrayMenuItem(text, action)` | 系统托盘菜单 | 点击托盘项 |
| `registerFloatingBallMenuItem(text, action)` | 悬浮球右键菜单 | 点击菜单项 |
| `registerSettingsPanel(title, panel)` | 设置窗口（标题分组） | 打开设置窗口 |
| `registerFloatingBallPickHandler(handler)` | 悬浮球名字抽取前 | 见 2.3 |

所有 `action` 均在 Swing 事件线程执行。

#### ② UI 篡改接口（主程序明确留出的界面改造通道）

| 方法 | 作用 |
| --- | --- |
| `setMainDisplayText(text)` | 直接修改主窗口中央显示文本 |
| `registerMainComponent(component)` | 向主窗口底部插件区注入任意 Swing 组件 |
| `addMainMenu(menu)` | 向主窗口菜单栏注入自定义 `JMenu` |
| `getMainApp()` | 获取主窗口实例（`NamePickerApp`），可自由改造 UI 与调用服务（高级入口） |

> “篡改”是特性而非漏洞：主程序主动暴露这些接口，供插件在不改主程序源码的前提下
> 修改界面。插件通过 `getMainApp()` 拿到窗口后，理论上可以改动任何公开组件。

#### ③ 服务与数据访问

| 方法 | 返回 |
| --- | --- |
| `getNameManager()` | `NameManager`：名单增删/导入导出/保存 |
| `getSchemeManager()` | `SchemeManager`：方案、数字范围、座位配置 |
| `getCurrentScheme()` | `Scheme`（public 模型：getName/getType） |
| `getCurrentMode()` | `"名字列表模式"` / `"数字模式"` / `"座位模式"` |
| `getPickCount()` | 单次抽取数量（多人点名设置，最小 1） |

### 2.3 FloatingBallPickHandler（悬浮球抽取拦截扩展点）

```java
public interface FloatingBallPickHandler {
    boolean onNamePick(FloatingBall ball, Scheme scheme,
                       java.util.List<String> names, int pickCount);
}
```

- 悬浮球每次执行**名字抽取**前，依次询问所有已注册拦截器；
- 返回 `true` 表示“本次抽取已由插件接管”，主程序不再执行默认单人滚动；
- 返回 `false` 表示交给主程序默认处理；
- `ball` 为触发抽取的悬浮球实例，插件可调用其公开方法：
  - `setDisplayText(String)` 修改球面文字
  - `getBallRadius()` 获取半径
  - `repaintBall()` 重绘
  - `getLocationOnScreen()` 等（继承自 Window）
- 示例：`MultiBallPlugin` 在 `pickCount > 1` 时接管并展示多球动画（见《插件开发文档》第 4 节）。

### 2.4 插件可用的其他主程序公开 API

| 类/方法 | 说明 |
| --- | --- |
| `NamePickerApp.pickDistinct(List, int, SecureRandom)` | 不重复随机抽取（static） |
| `NamePickerApp.getFloatingBall()` | 获取当前悬浮球实例（可能为 null） |
| `ConfigManager` | 全局配置读写（get/set 各配置项，static） |
| `LogManager.log(data, operation)` | 写操作日志（static） |
| `Scheme` / `NumberRange` / `SeatConfig` | 领域模型（public） |

## 3. 主程序扩展点汇总（视图）

```
主窗口 ──┬─ 菜单栏“插件”菜单        ← registerMainMenuItem / addMainMenu
         └─ 底部插件按钮区           ← registerMainButton / registerMainComponent
设置窗口 ── 插件面板区               ← registerSettingsPanel
系统托盘 ── 托盘菜单                 ← registerTrayMenuItem
悬浮球   ── 右键菜单                 ← registerFloatingBallMenuItem
         └─ 名字抽取前拦截           ← registerFloatingBallPickHandler
主窗口中央 ── 显示文本               ← setMainDisplayText
全局     ── 主窗口实例 / 服务        ← getMainApp / getNameManager / getSchemeManager
```

## 4. 已发布插件一览

| 插件 | 扩展点使用 | 说明 |
| --- | --- | --- |
| 多悬浮球插件(示例插件) `MultiBallPlugin` | 抽取拦截 + 悬浮球菜单 + 设置面板 | 多人点名多球动画（透明度/多环防重叠，子球无尾迹） |

## 5. 插件管理与状态联动

- **启用状态持久化**：`data/config.properties` 中的 `pluginEnabled.<Plugin-Class 值>`（默认 `true`）；
- **插件管理界面**：主窗口“插件”菜单 / 悬浮球右键菜单 → “插件管理”：
  - 查看插件列表（名称、版本、状态：启用中 / 已禁用 / 未安装）；
  - 启用 / 禁用（即时生效：插件被立即加载/卸载，其注册的菜单、按钮、面板与抽取拦截器同步增删）；
  - 卸载（删除 `extensions/` 下对应 JAR）；安装（选择 JAR 复制到 `extensions/`，安装即启用）；
- **设置联动**：主程序可调用 `PluginManager.isPluginEnabled(id)` 判断插件是否安装且启用，从而动态显示/隐藏相关设置项（例如“单次抽取数量”仅在“多悬浮球插件”启用时显示，否则置灰提示“未安装或未启用多球抽取插件”）；
- **限制**：托盘菜单在启动时构建一次，插件启用状态变化后需重启程序刷新；
- 已知插件标识常量：`PluginManager.PLUGIN_ID_MULTI_BALL`（多悬浮球插件）、`PluginManager.PLUGIN_ID_PEN`（屏幕画笔插件）。

## 6. 线程与生命周期约定

1. `onLoad` 在主窗口构造期间（EDT）调用，可安全操作 Swing 组件；
2. 扩展点回调均在 EDT 执行，插件内耗时操作请自行开线程；
3. `onUnload` 在程序退出前调用（可能非 EDT 兜底路径），请勿在其中弹窗；
4. 插件持有的窗口在 `onUnload` 中应自行 dispose（如动画窗口、画布窗口）。
